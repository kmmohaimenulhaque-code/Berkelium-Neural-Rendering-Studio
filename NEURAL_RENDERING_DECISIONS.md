# Neural Rendering Decisions

**Revision:** `NR-0.5` (2026-10-16)  
**Status:** D-001..D-010 proposed (NR-0.2); D-011..D-016 adopted (NR-0.3); D-017..D-022 adopted and implemented in NR-0.4; D-023..D-028 (E-T3); D-029..D-032 written before the results they decide (NR-0.5; see `docs/ENGINEERING_LOG.md`).

Evidence labels: `[O]` inspected implementation observation, `[F]` external source fact, `[D]` Berkelium decision, `[H]` hypothesis requiring an experiment.

## Decision register

| ID | Decision | Rationale | Revisit trigger |
| --- | --- | --- | --- |
| D-001 | `[D]` Keep the desktop renderer untrusted; use a narrow preload/main bridge, loopback FastAPI, and a trusted worker. | `[O]` The current Electron window has Node integration enabled and no preload; direct renderer HTTP also exposes the backend boundary. | A measured alternative provides equal isolation and auditable authorization. |
| D-002 | `[D]` Keep Phase 1 read-only. No training, scene mutation, arbitrary commands, or job submission is enabled by documentation. | `[O]` README Phase 1 excludes mutation and neural training; the current API has no neural routes. | A later approved phase passes auth, persistence, worker-isolation, and migration gates. |
| D-003 | `[D]` Berkelium owns an independent CPU reference and HIP/C++ renderer contract. | Avoid importing Graphdeco's restricted implementation; keep CPU semantics and HIP behavior testable without model weights. | License review authorizes a compatible backend and parity testing justifies an adapter. |
| D-004 | `[D]` Canonical scene storage is GaussianScene v1 metadata plus checksummed binary arrays; meshes, images, CAD, checkpoints, and reports stay distinct artifact kinds. | Prevents a `.ply`, mesh, or preview from being misrepresented as a CAD or measured scene. | A versioned interchange requirement proves a different representation is necessary. |
| D-005 | `[D]` Use right-handed +Y-up world coordinates and OpenCV +Z-forward camera coordinates with explicit adapters. | Avoids silent Blender/OpenGL/COLMAP/MVDream basis and pose inversions. | A concrete external format requires a new canonical basis and all fixtures are migrated. |
| D-006 | `[D]` First text-to-3D path is Z-Image-Turbo → human-reviewed image → TripoSR explicit 3D prior → optional Gaussian fitting. | It avoids making independent view prompts appear calibrated and avoids making Zero123++/InstantMesh's non-commercial weights a default dependency. | A licensed direct or joint-multiview system wins the same control geometry/consistency gates. |
| D-007 | `[D]` Treat Mip-NeRF 360 as a real-capture/unbounded-scene comparison, not text-to-3D supervision. | Its posed-capture objective and scene normalization differ from prompt generation. | A matched permitted dataset and protocol establish a valid cross-representation comparison. |
| D-008 | `[D]` CPU analytic/finite-difference fixtures precede any MI300X allocation; first allocation is one GPU and at most 1.5 billed GPU-hours. | Reduces paid debugging and catches camera/math errors without hardware. | Provider billing or allocation inventory changes the approved envelope. |
| D-009 | `[D]` Protect at least 8 GPU-hours and never infer cost from wall time alone. | Provider billing unit, GPU count, rounding, and balance are not verified. | A provider receipt establishes a different accounting model. |
| D-010 | `[D]` Use canonical job states `pending`, `running`, `completed`, `failed`, `cancelled`, `checkpointed`, and `resumed`; keep experiment outcomes in receipts. | Separates lifecycle state from research results such as `blocked` or `correctness_pass/performance_stop`. | A versioned API migration defines a replacement state machine. |

## NR-0.3 decisions (implemented)

| ID | Decision | Rationale | Revisit trigger |
| --- | --- | --- | --- |
| D-011 | `[D]` AMD gsplat (AMD-Ecosystem/gsplat tag `v1.5.3b2`, `ff8bc548`) is the differentiable-rendering foundation. **Revises D-003**: Berkelium no longer re-implements the full forward on HIP; it keeps an independent CPU reference (oracle) and contributes original HIP extensions on top of gsplat. | Owner directive; gsplat is Apache-2.0 + MIT (AMD), ROCm-supported on MI300X. Only `release/1.5.3b2` contains the ROCm port (`main`/`amd-main` = upstream). | AMD publishes a newer ROCm release or the pin fails on the provider image. |
| D-012 | `[D]` First Berkelium HIP extension: an atomic-free, deterministic rasterization backward (per-intersection gradient slots + fixed-order reductions) replacing gsplat's float `atomicAdd` accumulation for the same forward. | Measurable, falsifiable contribution: bitwise-repeatable gradients with gsplat-equal values; spec §8 asks for deterministic accumulation. | GPU measurements show the overhead is unacceptable for training; then add a wave-shuffle fast path with the same fixed order. |
| D-013 | `[D]` HIP source is validated on CPU by compiling the unmodified `.hip` file against AMD's HIP-CPU runtime (pinned `e112c93`). Labelled `cpu_emulated_hip`; never reported as GPU evidence. | Catches logic, barrier and indexing errors before spending MI300X credit. | n/a |
| D-014 | `[D]` First text-to-3D slice = Berkelium-owned procedural dataset with exact analytic SDF ground truth + a small Berkelium text-conditioned SDF generator trained from scratch, with a LoRA(+token-embedding-delta) adapter as the fine-tuning mechanism. D-006 (Z-Image → TripoSR) stays a candidate requiring download approval. | Real 3D output, real training, owned licence, independent geometric ground truth, CPU-feasible; avoids claiming fine-tuning support for models whose stacks are not set up. | A licensed pretrained text-to-3D model is approved and wins on the same protocol. |
| D-015 | `[D]` Rendering profiles are explicit (`gsplat_v1`, `berkelium_v02`); comparisons only within one profile. | gsplat (exclusive 1e-4 stop, 1/255 cutoff, cap 0.999) and spec v0.2 (inclusive stop, 3-sigma support, cap 0.99) are different functions; mixing them would mislabel semantic differences as kernel errors. | n/a |
| D-016 | `[D]` The Studio renderer talks to the backend over HTTP at a configurable base URL (existing pattern), fetching only typed JSON and immutable artifacts by id. | Keeps the existing Phase-1 transport; D-001's main-process bridge for neural calls remains open work. | Security review requires moving neural calls behind preload IPC. |
| D-017 | `[D]` Text-to-3D is a feature of main's Studio scene editor, not a separate viewer: a generated mesh is imported through the same path as a user file (scene node, undo, transform), and the Gaussian scene is shown as the backend's splat render. "Render this view" sends the live viewport camera, converted to an OpenCV `CameraSpec` in the model's frame (`scene/neuralCamera.js`, unit-tested against three.js projection). | One product, one scene; the render the user sees is produced by the real renderer from the camera they chose, never a client-side imitation. | A WebGL splat viewer is validated pixel-for-pixel against the reference renderer. |
| D-018 | `[D]` Adapter routing: `adapter="auto"` (Studio default) applies a concept adapter only when the prompt names its concept (`text3d/routing.py`, whole-word match on `adapter_config.new_tokens`). The same function drives the service and the benchmark (E-T2). | `[O]` E-T1: the capsule adapter improves capsule prompts but degrades base prompts (retention regression); routing keeps base behaviour elsewhere. | An adapter trained with base-data replay matches base quality on base prompts (E-T1 retention comparison). |
| D-019 | `[D]` M8 policy transition out of Phase 1: the backend worker may create artifacts (write-once, content-addressed) and job records; it never mutates user projects, scenes or files. Every stage is resumable: the mesh stage and the Gaussian fit checkpoint in the job workdir, and a resumed job reuses what it already published. Job reads report missing artifact records instead of serving them. | Durable jobs without duplicate or orphaned results after a crash; the user's scene is changed only by the user's own import action in Studio. | Multi-worker execution or remote storage. |
| D-020 | `[D]` M6 compatibility branch for TripoSR on non-CUDA hosts: `torchmcubes` is replaced by scikit-image marching cubes behind a shim with torchmcubes' axis convention; `rembg` is not used (control images carry exact alpha). TripoSR runs in its own environment (`.venv-triposr`, transformers < 5 because transformers 5 renamed the ViT parameters in the pinned checkpoint). | `[O]` Verified on CPU (M6 receipt); keeps the pinned weights and model code unmodified. | AMD-verified torchmcubes or an upstream fix. |
| D-021 | `[D]` M7 real-object data = Google Scanned Objects (CC-BY 4.0), pinned per object by zip sha256. Observations are renders of the textured scan from known cameras, labelled as such (not photographs). The fit sees only training observations; initialisation is space carving from training silhouettes; the scan is used only to render observations and to evaluate geometry. | A real-object dataset with a clear licence and exact poses that runs on CPU; avoids confusing mesh-to-Gaussian conversion with fitting. | A licensed real capture with calibrated photographs (e.g. a CO3D/MVImgNet subset) is approved. |
| D-022 | `[D]` M5 (Z-Image-Turbo, ~33 GB snapshot, 6B DiT) is a GPU-only smoke test with a preflight that records blockers instead of attempting CPU inference; it runs only with `--i-approve-gpu-cost`. | `[O]` This development host has no GPU, 7.8 GB RAM and 15 GB free disk; the snapshot cannot be loaded here. | An approved MI300X session. |

## E-T3 open-world decisions (implemented 2026-10-15)

| ID | Decision | Rationale | Revisit trigger |
| --- | --- | --- | --- |
| D-023 | `[D]` Open-world text-to-3D uses a **pretrained** prior, Shap-E text300M + vector decoder (OpenAI, MIT; code `50131012`, weights sha256-pinned), on CPU, behind a generator interface (`text3d/generators.py`). The native BerkeliumTextShape model is kept unchanged. No model is trained or fine-tuned for this. | `[O]` The native model has a 30-token vocabulary learned from scratch: "a wooden chair with four legs" is 4 `<unk>` of 6 tokens. More training on the same grammar cannot add knowledge it never saw. `[O]` P2: Shap-E runs here (827 s per 16-step generation, 2.6 GB peak RSS) and produced a recognisable chair. | The D-006 image-prior path (Z-Image → TripoSR) runs on a GPU and beats Shap-E on E-T3, or a licensed stronger text-to-3D model is approved. |
| D-024 | `[D]` `auto` routing: the native model iff every content word (non-stopword) of the prompt is in its vocabulary, otherwise Shap-E. There is no synonym table, so "cube" goes to Shap-E. An unavailable routed generator is refused with its reason at submission, never silently replaced. | Deterministic and auditable. It keeps the native model where it was measured (procedural prompts) and never sends it words it reads as `<unk>`. | E-T3 shows Shap-E beating native on in-vocabulary prompts, or a routed prompt class failing systematically. |
| D-025 | `[D]` CLIP ViT-L/14's text tower is extracted once into `clip_vit_l14_text.pt`, bit-for-bit, by a restricted unpickler over the TorchScript zip. It records the source sha256. At run time `clip.model.CLIP`'s own text code is rebuilt with a 1-parameter vision stub. Neither `torch.jit.load` nor `clip.load` is used. | `[O]` `torch.jit.load` of ViT-L-14.pt exceeded 3.2 GB RSS while holding the GIL and was SIGTERMed by this host's memory watchdog (twice). The extraction peaks at 1.5 GB. Unit test: the rebuilt text tower equals the full model's `encode_text` bitwise (small CLIP). | Upstream CLIP ships non-TorchScript weights, or the host has more memory. |
| D-026 | `[D]` The service runs Shap-E in a child process (`text3d/shap_e_worker.py`). It has a `/proc` memory guard (exit 86 at 3.1 GB), streams JSON stage progress (loading → sampling → decoding → validating), is cancelled by terminating the child, and reuses a finished child result from the job workdir on resume. Models are built with `torch.nn.init` disabled and the memory-mapped checkpoint is assigned in their place (strict), so the random-init buffers never become resident. A worker is not started below 2,000 MiB MemAvailable (`RESOURCE_LIMIT`). | The API server never holds the weights, and a memory kill fails one job, not the service. Cancellation takes effect within 0.5 s, not at the end of a 13-minute run. `[O]` The host watchdog acts on system-wide free memory (~0.8 GB): a second worker was SIGTERMed while loading. Skip-init cut the loading peak from 2.3 to 1.1 GB anonymous. | A GPU worker pool or a separate inference service. |
| D-027 | `[D]` Two-object scenes come from a deterministic parser (`text3d/planner.py`: on top of / stacked on / with … on top / on, next to / beside / left/right of / and; both objects must start with a/an/the/one). Each object is generated and validated separately and placed by bounding box with the procedural GT's conventions (touching stack, 0.2 gap, size words 0.7/1.3, scene extent 1.6). Parts are stored separately with explicit 4x4 transforms. There is no LLM. | Composition the native model was not trained for, and open-world objects in a relation, with editable parts and no hidden model. | Prompts with more than two objects, or relations beyond stacking/side-by-side. |
| D-028 | `[D]` E-T3 scoring extends, never changes, `berkelium-text3d-eval/1`. Open-world geometry uses a deliberately generous alignment applied to every generator: unit extent, best of 24 axis rotations, then rigid ICP. Semantic relevance uses CLIP R-precision with an evaluator (ViT-B/32) that is not the conditioner (ViT-L/14). Composition adds a touch-merged component count (tolerance 0.02) applied identically to GT and predictions. | Fair comparison across generators with different frame conventions. Avoids scoring Shap-E with its own conditioner. Makes the existing rule "touching parts merge" explicit for multi-part assemblies. The residual bias of shared OpenAI-CLIP lineage is stated in the results. | A licensed evaluator from a different lineage (e.g. a non-OpenAI CLIP) is approved. |

## Federated GPU and evidence-gated routing (written 2026-10-16, before the results they decide)

| ID | Decision | Rationale | Revisit trigger |
| --- | --- | --- | --- |
| D-029 | `[D]` The `auto` router keeps the native rule for prompts the native model can read and otherwise uses the first *available* generator of an evidence-ordered list (`OPEN_WORLD_RANKING`, `text3d/generators.py`). **Pre-registered order rule:** `zimage-triposr` ranks above `shap-e-text300m` iff, on E-T3, (a) B1 mean F@0.05 with failed units counted as 0 is ≥ Shap-E's, (b) B1 mean Chamfer-L1 over its valid units is ≤ Shap-E's, and (c) B2 R@1 is ≥ Shap-E's; otherwise Shap-E stays first. A ranked generator that is unavailable on the host (no GPU) is skipped and the skip, with its reason, is written into the job report and the Studio provenance card; auto never hands an unreadable prompt to the native model. | The evidence decides the default, and a CPU-only host still answers with the next-best measured generator instead of refusing. 12 B1 objects and 20 B2 prompts are a small sample: the rule is a decision rule, not a significance claim, and auto's E-T3 scores after the choice are in-sample. | A larger frozen benchmark, or a generator that wins on one block and loses on another by a wide margin. |
| D-030 | `[D]` The canonical 3D-anchor LoRA (`exports/zimage-anchor-lora-v1`, Phase II.2) replaces the base Z-Image anchor stage only if its own E-T3 units (`zimage-triposr-anchorlora`) meet all of: B1 valid rate ≥ base, B1 mean F@0.05 (failures as 0) > base, B1 mean Chamfer-L1 (valid) ≤ base, B2 R@1 ≥ base. Training data excludes every B1/B2 category and all procedural shapes (`configs/datasets/anchor_lora_gso_v1.json`). | A fine-tune of a distilled 8-step model can degrade it; only the benchmark may promote it. | — |
| D-031 | `[D]` Capsule adapter v2 (experience replay of the base training families + a signed-distance separation margin, `configs/adapters/textshape_lora_capsule_v2_replay.json`) replaces capsule-v1 in adapter routing only under the promotion rule stored in that config (part-count accuracy ≥ 0.53 on adapter_test; Chamfer non-inferior to v1 within +0.010 at the CI upper bound; Chamfer gain over base kept). | Fixes the E-T1 part-merging regression without giving up the measured capsule geometry, or is reported as not fixing it. | — |
| D-032 | `[D]` Heavy compute runs on Kaggle GPU kernels through `scripts/kaggle_gpu_runner.py`: the code shipped is a hashed bundle of this working tree, every returned file is re-hashed against the remote manifest before it is admitted, and failed remote steps stop the job (no retries). Kaggle T4 results are CUDA evidence only; they are never reported as ROCm/AMD evidence. Small CPU-feasible training (the 362k-parameter native adapter) stays on the CPU host, where it is bitwise reproducible. | One verifiable path for every GPU artifact; the dev host has no GPU. | An approved MI300X session (same runner pattern, ROCm image). |

| D-033 | `[D]` **Design compiler (E-C1), pre-registered 2026-10-17 before any training.** Qwen3-8B (`b968826d`) + the cad LoRA ("m2", `scripts/cad_train.py`, data `berkelium-cad-v1`) becomes the Studio `cad` generator only if, scored by the Berkelium core (`scripts/cad_eval.py`, NF4 on Kaggle T4, greedy, thinking off) on held-out data: (1) test (unseen seeds of trained families) schema-valid ≥ 0.95, (2) test realise ≥ 0.90, (3) test reference-requirement pass ≥ 0.85, (4) held-out families (`pipe_elbow`, `chair`, `knob`, `hinge_leaf`, never trained) realise ≥ 0.60, (5) held-out IoU beats zero-shot Qwen3-8B with the paired bootstrap 95 % CI above 0, (6) gear requirement match not below zero-shot. Measurement/validation fields in a proposal are schema errors (counted as failures). | The model only proposes; the core decides. The thresholds were set before the data existed; held-out families measure reach beyond the templates. | A hand-written prompt set from real users, or a teacher-paraphrased text set. |

### Outcomes (applied 2026-10-16/17, numbers in results/)

- **D-029:** zimage-triposr v2 vs Shap-E on E-T3: B1 F@0.05 0.603 vs 0.669, B1 Chamfer 0.055 vs 0.047, B2 R@1 0.85 vs 0.95 → none met; `OPEN_WORLD_RANKING = (shap-e-text300m, zimage-triposr)`. v2 is better on composition (B4 part count 0.50 with the planner vs 0.00) and B3 geometry.
- **D-030:** anchor LoRA vs base v2: 1 of 4 criteria met (valid rate); F@0.05 0.546, Chamfer 0.060, B2 R@1 0.25 → not promoted.
- **D-031:** capsule v2: part count 0.40 (< 0.53), Chamfer +0.018 vs v1 → not promoted; capsule-v1 stays.
- zimage-triposr stage 3 changed from colour keying (v1, 37/80 valid) to U²-Net segmentation (v2, 80/80) after v1's rejections were seen and before any geometry was scored; both are scored separately.

## Rejected or deferred choices

- `[D]` Do not use the original Graphdeco implementation as Berkelium source; its license is restrictive for the intended product posture.
- `[D]` Do not use Zero123++ v1.2/InstantMesh as the default production path; Zero123++ weights are CC-BY-NC-4.0 and every fine-tuned/base component requires separate review.
- `[D]` Do not claim AMD support from a CUDA wheel, a successful import, or the presence of `cuda:0` in PyTorch HIP.
- `[D]` Do not call a mesh, NeRF, or Gaussian preview a CAD model or measured geometry without a separate accuracy and units contract.
- `[H]` Do not assume TripoSR's CUDA extraction extension works on ROCm; CPU extraction or a verified replacement is the first compatibility branch (CPU replacement verified: D-020; ROCm still unverified).

## Consequences

These decisions intentionally delay polished end-to-end generation. They make the first measurable result a reproducible renderer contract and artifact lineage, not an attractive but unverified image. Detailed interfaces are in `NEURAL_RENDERING_API.md`, numeric semantics in `GAUSSIAN_RENDERER_SPEC.md`, and execution ordering in `NEURAL_RENDERING_ROADMAP.md`.
